> **协作提示（2026-11-17）**：Claude 在 `claude/design-on-14nodes`，Codex 在 `codex/workspace` 各自提交；`main` 仅供审核后的集成。详细规则见 [Claude / Codex 协作与分支规范](docs/协作分支规范.md)，根目录另有 `CLAUDE.md`、`AGENTS.md` 供开发助手读取。

万水千山，从一个人说起：真人真事，皆有出处。助手“小征”讲述长征路上有出处的故事，也回答和查证关于长征的问题。观众提问，或贴一句关于长征的说法，助手“小征”查阅有出处的史料、核对后回答，查不到会直接说明。**目前收录的是中央红军主力的长征路线**（中央苏区至吴起镇，共 23 处），另有到陕北之后的直罗镇和红军三大主力会师；红二、红四方面军和红二十五军的长征只有少量资料。地图为示意。知识库包含 26 个节点、120 条扩展资料、已审核的故事和专题资料（其中 2 条是人数统计来源辨析而非人物故事）。

“小征”是一个工具调用智能体：模型自己决定查阅哪些资料（按节点、按编号、关键词检索）、要不要操作页面（打开某一站、下一站、定制路线），回答只能引用本次取出的资料，并经服务端核对出处、数字和文件名；处理过程在对话中实时显示。

## 本地运行

需要 Node.js 18 或更新版本，无需安装额外依赖。

```sh
npm run build
npm test
npm run dev
# 可选：检索评估（不调用模型，只测检索工具的命中率）
npm run eval:retrieval
# 可选：联网核查当前全部史料链接是否可打开（去重后的数量以脚本输出为准）
npm run check:sources
```

真实模型评估：按《问答评估清单》逐项调用讲解员接口，生成《问答评估结果-日期》文档，人工判定一栏留空待填。需要 DeepSeek 密钥，或用 `EVAL_BASE_URL` 指向已部署站点：

```sh
DEEPSEEK_API_KEY=你的密钥 npm run eval
```

回答依据审计：用常规题、诱导编造题和多轮施压题检查回答是否只来自知识库，逐句比对所引资料并标出可疑句子，生成《回答依据审计-日期》：

```sh
DEEPSEEK_API_KEY=你的密钥 npm run audit
```

知识库原文比对：抓取每条资料的来源网页，逐句比对资料文字与原文，标出原文中找不到依据的句子（云端环境需加 `HTTP_PROXY="$HTTPS_PROXY" NODE_USE_ENV_PROXY=1`）：

```sh
npm run check:kb
```

本地预览打开 `http://127.0.0.1:4173`。本地预览默认不载入 API 密钥，能浏览页面和路线，模型问答会提示尚未配置；如需在本地试用真实问答，用 `DEEPSEEK_API_KEY=你的密钥 npm run dev` 启动（对话签名密钥自动随机生成，可用 `HOST`、`PORT` 改监听地址）；不要把密钥写入源码或前端。线上密钥由 Sites 服务端环境变量管理，包含 `DEEPSEEK_API_KEY` 和独立随机的 `HISTORY_SIGNING_KEY`；不得写入源码或前端。

- `src/server.js`：Worker 请求处理与模型调用。
- `scripts/generate.mjs`：将源文件合成为部署入口 `worker/index.js`。

### 问答与部署边界

- **馆内检索与引用**：`search_materials` 用 BM25 检索知识库正文。查询只含空格分隔的单字时，优先按连续词查找，双字检索没有结果时可回退到单字匹配。历史回答只能引用本轮取出的馆内资料。服务端核对引用 ID、数字、日期和书名。问句中的数字可在明确纠错时被否定，肯定性表述仍须有出处。失败后会提示重答，并尽量保留能通过规则核对的答句。规则检查的结果仍需结合原文核实。
- **联网搜索**：页面可主动联网，馆内答复缺少出处时也可触发联网补查。服务端调用 DeepSeek `deepseek_web_search`，默认模型为 `deepseek-flash`。部署时可用 `DEEPSEEK_WEB_MODEL` 配置支持该工具的模型，或用 `WEB_SEARCH=off` 关闭。网页链接来自联网接口的出处数据，和馆内引用分开显示，统一标为「网络来源 · 未经人工核对」。
- **对话上下文**：多轮历史由服务端签名，与页面会话、节点和当前阅读的篇章绑定，有效期一小时。联网答复留在当次对话展示中，后续馆内问答可用上一问理解指代。
- **参观路线**：预设路线按规则生成。精简路线由 `/api/plan` 从现有节点中选 3 站，服务端校验后按时间排序。完整路线覆盖全部节点。聊天中的定制路线工具支持 2–6 站，也可在对话中前往节点、继续或跳过。
- **请求限流**：默认每 IP 每 10 分钟可问答 30 次、规划 10 次，每运行实例每小时合计受理 600 次。可用 `CHAT_LIMIT_PER_IP`、`PLAN_LIMIT_PER_IP`、`MODEL_LIMIT_PER_HOUR` 调整。计数保存在实例内存中，重启后清零。无法识别客户端 IP 时只应用实例总限额。一条受理请求可能触发多次模型调用。公开部署前需单独核对访问范围和 DeepSeek 账户用量上限。
