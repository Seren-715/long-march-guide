# 《数字长征沙盘》创作文档说明（赛道二 · AI 编程）

> 作品形式：互动网页（单个 HTML 文件，离线可用，手机和电脑都能打开）
> 作品文件：`digital-march/index.html`　源码：`digital-march/`　设计文档：[赛道二-设计文档.md](赛道二-设计文档.md)
> 与赛道三作品《长征路上》（AI 讲解员“小征”）共用同一个知识库，但本作品是独立网页，运行时不调用任何模型、不联网。

## 一、创意构思

活动主题是“数字长征”。我们想做的不是一页把史料排出来的展板，而是让观众**亲手“走”一遍长征**，并且在每一步都能看到“这句话从哪里来”。

**一句话概括：** 一张能走的沙盘、一条电报纸带、一片人物星河——页面上每个日期、每个数字都能点开看到原文出处。

构思的几个出发点：

1. **用“走”代替“读”。** 长征的核心是“一年、两万五千里”的行进。页面开篇用一笔红线画出中央红军的路线走向（“一笔长征”）；进入沙盘后，观众每向下滚动一屏，红旗就前进一站，路线被染红，镜头推到这一站，电报纸带打出日期和“出发后第几天”。
2. **用当时的媒介做界面。** 长征中的指挥靠电台和电报（知识库资料：四渡赤水期间中革军委和各军团用电台组成无线电通信网络；通道会议后发出“万万火急”电令）。所以页面顶部的日期条做成电报纸带，会议列表做成带穿孔的纸带。
3. **把复杂机动讲清楚，又不编路线。** 四渡赤水是最难讲清的一段。我们没有画“想象中的行军箭头”，而是做了一张“时间—河岸”示意图：横轴只分西岸、东岸，纵轴是时间，红线随步骤在两岸之间来回折返，四次渡河一目了然，同时注明“不表示实际位置和路线”。
4. **用数据说话，也讲清数据的边界。** 四路红军的起止和里程、中央红军三个时间点的人数，都用图表呈现；人数图下方专门说明“差额不能都看作伤亡”，因为其间有缩编和部队分开行动。
5. **人物不是孤立的名单。** “人物星河”把站点按沙盘位置排成一条星座，人物是星，连线表示他（她）在哪几站的资料里出现。点刘伯承，能看到他从黎平、金沙江、彝海一路连到大渡河。
6. **学完能检验，也能带走。** “行军考场”从知识库自动组卷，每题答完给出原文与出处；最后生成一张属于自己的“行军卡”图片（走过几站、读过几篇故事、答题成绩，可署名）。

## 二、史实规则（最重要的设计约束）

- **只用已有、有出处的资料。** 全部内容取自本仓库知识库：26 个节点、146 条节点资料、39 篇已审核故事（`reviewed: true`）、24 条人物资料。未审核的故事不进入页面。
- **数字和日期“可追溯”。** 页面上图表用到的每个日期、数字、会议决定，都在 `digital-march/src/facts.js` 中写成“资料 ID + 原文片段”。构建时程序逐条到资料原文中查找这个片段，**找不到就中止构建**。目前共核对 26 个日期锚点、17 次会议、12 道数字题、9 张数字卡片、8 个四渡赤水步骤等。
- **不增加对白、心理和情节。** 故事正文直接取知识库原文；会议“决定”一栏原样显示资料原文，不作改写。
- **示意就写明是示意。** 沙盘是地形示意，不画边界、不标行政区；四渡赤水图不表示实际位置；“出发后第几天”按资料日期推算，起点是 1934 年 10 月 10 日（中共中央、中革军委从瑞金等地出发）；只到月份的日期（如威逼昆明 1935 年 4 月）不做推算。
- **资料之间的分歧照原文保留**（如李德是否出席黎平会议、授旗时间等），不替资料“下结论”。

## 三、使用的 AI 工具

| 工具 | 用途 | 人工把关 |
| --- | --- | --- |
| Claude Code（Anthropic 的编程智能体） | 阅读仓库已有知识库与地图数据；设计页面结构与交互；编写构建脚本、页面样式与脚本、回归检查；在无头浏览器中截图检查电脑和手机布局 | 所有结构化事实都由构建脚本对照资料原文核对；页面文字的史实部分只取知识库原文 |
| Blender（沿用赛道三作品的沙盘渲染结果） | 沙盘地形图 `src/assets/longmarch-map.webp` | 地形示意，不作地图使用 |
| 知识库原有的 AI 辅助整理流程 | 知识库资料的收集与整理（见 `docs/知识库说明.md`） | 每条资料对应公开网页，已审核标记见各文件 |

说明：页面运行时**不调用任何 AI 模型**，问答题由程序从资料原文组卷，避免模型“现编”史实。

## 四、功能介绍

| 章节 | 交互 | 说明 |
| --- | --- | --- |
| 开篇 · 二万五千里 | 红线一笔画出路线；“长征路上的今天”按日历找出离今天最近的长征日子 | 数字条（8.6 万余人、一年、11 个省、2.5 万里）每项可点“源”看原文 |
| 壹 · 行军沙盘 | 滚动前进 / 点地图圆点或刻度跳站 / 方向键切换 / “自动行军” | 23 站主路线 + 3 处到达陕北之后的站点；电报纸带显示日期与出发后天数；每站可展开全部资料、打开相关故事 |
| 贰 · 四渡赤水 | 上一步 / 下一步 / 自动演示；点列表任一步 | 时间—河岸示意图，计数“已渡 n / 4” |
| 叁 · 数字里的长征 | 点甘特图条形看起止与里程，点菱形看会师节点；点卡片翻面看原文 | 四路红军时间轴、中央红军人数（附说明）、9 张数字卡片 |
| 肆 · 一路开会，一路转折 | 纸带横向滑动、左右键切换；“在沙盘上看” | 17 次会议，小地图同步标出位置并染红已走路线 |
| 伍 · 人物星河 | 点人物或站点，连线高亮 | 24 位人物，列出其出现的站点资料与相关故事 |
| 陆 · 长征故事 | 按 8 个专题筛选；阅读框内上一篇 / 下一篇 | 39 篇已审核故事 + 1 篇事件故事（四渡赤水），附注与全部出处 |
| 柒 · 行军考场 | 每轮 10 题，四种题型（数字、会议、人物、排序 + 时间），每轮重新组卷 | 每题答完给出原文与出处；记录最好成绩 |
| 捌 · 长征是宣言书 | 生成行军卡（可署名）、保存图片 | 引文与长征精神原文；“资料从哪里来 / 怎样保证不编造 / 怎么看这一页”三段方法说明 |

其他：深浅色主题切换；尊重系统“减少动态效果”设置；全部按钮可用键盘操作；阅读进度、答题成绩只保存在本机浏览器，不收集任何个人信息。

## 五、运行与提交材料

- **打开方式**：直接用浏览器打开 `digital-march/index.html`（离线可用）；也可以放到任意静态网站托管。
- **在线链接**：将上述文件发布后的链接填入报名表（如需，可部署到 GitHub Pages 等静态托管）。
- **源码**：`digital-march/`（`src/` 为源文件，`build.mjs` 构建，`check.mjs` 检查）。
- **设计文档**：[赛道二-设计文档.md](赛道二-设计文档.md)。

```bash
npm run build:march   # 从知识库重新生成 digital-march/index.html
npm run test:march    # 资料核对 + 单文件检查 + 浏览器走查（电脑、手机两种尺寸）
```
