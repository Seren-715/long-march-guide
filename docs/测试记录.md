## 2026-11-14 讲解员（智能体）改进

针对设计评审列出的问题修改 `src/server.js` 与 `src/page.html`，知识库数据未改。

- **限流**：模型调用前按 IP 计数（问答每 10 分钟 30 次、规划 10 次）并限制每个实例每小时总量 600 次，超出返回 429；数值可用环境变量调整。计数只在单个实例内存中有效，不能替代模型服务账户侧的费用上限。
- **输出长度**：`max_tokens` 由 500 提高到 900，提示词要求回答不超过 300 字；模型输出因长度截断（`finish_reason: length`）时视为格式错误并重试。
- **问题分类**：模型先判断 history / chat / off_topic。问候、感谢、使用说明不再一律回复“资料不足”；自称闲聊却引用资料或含三位以上数字的回复，按历史问题处理。
- **数字核对**：历史回答中的阿拉伯数字必须出现在所引资料或用户问题中；不符时带校验提示重试一次，仍不符则降级为“资料不足”。该检查不覆盖汉字数字和非数字论断。
- **链接措辞**：服务端删除回答中谈论“链接/网址”的句子和网址，解决评估第 15 项“不能提供链接”与页面出处矛盾的问题。
- **页面操作**：模型可返回前往节点、下一站、跳过、开始预设路线四类操作，服务端校验节点 ID 与路线键后返回，页面执行；原有固定句式快捷指令保留，模型未配置时仍可用。
- **参观上下文**：页面发送当前路线与已看过的节点 ID，服务端只保留已知 ID 写入系统提示，不接收路线名称等自由文本。
- **追问建议**：每个回答最多附两条不超过 30 字的追问，过滤网址和重复项；页面显示为可点击按钮。
- **换站衔接**：点“下一站”时，小征不再复述左侧正文，改为说明从哪一站来到哪一站、这是路线第几站、还剩几站，并附本站推荐问题。
- **AI 规划理由**：由系统根据实际选中的节点生成，例如“按你的描述，从 14 个节点中选了「中央苏区」「遵义」「吴起镇」”，不展示模型自由撰写的理由。

验证：`npm test` 通过，新增断言覆盖规划理由、chat/off_topic 类型、闲聊含年份降级、数字不符时的校验重试与降级、问题中数字可复述、截断重试、链接句删除、操作校验（合法、非法节点、当前节点、非法路线）、追问过滤、参观上下文只保留已知 ID、按 IP 限流返回 429。Playwright 模拟接口在 1440×900 与 390×844 检查：换站衔接语正确；闲聊回答不显示“提问时的节点”并显示追问按钮，点击后发出该问题；请求体包含路线与已看过节点；“我想看看飞夺泸定桥那段”返回的前往操作使页面切到泸定桥（手机端切回讲解页）；next 操作前进到吴起镇；429 时输入框保留问题；无横向滚动，无非预期控制台错误。

## 小征改造为工具调用智能体（2026-11-15）

目的：原来每次问答只调用一次模型、把全部资料放进提示词，更像问答机器人。改为模型自己调用工具、多步完成，并把过程显示出来。

改动：
- 服务端 `/api/chat` 改为工具调用循环。8 个工具：`read_stop`、`read_materials`、`search_materials`（查资料）；`open_stop`、`tour_control`、`start_route`、`plan_route`、`show_quiz`（操作页面）。
- 提示词不再包含全部资料，只给资料目录（编号和开头）与当前节点资料；回答只能引用本次取出的资料，引用未取出的资料会被提醒一次，仍然如此则按“资料不足”处理。
- 原有校验全部保留（出处白名单、数字、书名号、高风险表述、闲聊不带史实、去链接），不合格重答一次。
- 新增页面操作：`plan`（按兴趣和时间定制 2—6 站路线）、`quiz`（打开小测题）。一次回答只执行第一个页面操作。
- 页面以流式（NDJSON）接收处理步骤并实时显示，回答出现后保留在回答上方；`scripts/dev.mjs` 改为逐块转发。
- 单次引用上限由 4 条提高到 6 条（跨节点问题常需要 5 条以上）。
- 顺带修复：纯对话模式下开始路线时没有退出纯对话。

验证：
- `npm test` 通过。新增用例：先取资料才能引用、未取就引用的提醒与降级、当前节点预取、检索与按编号读取、定制路线排序与数量限制、出题不泄露答案、一次只执行第一个操作、无路线时“下一站”不执行、工具调用上限、流式输出格式与错误。
- 真实模型评估（`npm run eval`，共 47 项，新增第 38—43 项智能体用例）：改造完成后连续三轮结果为 46/47、47/47、47/47，最终结果见《问答评估结果-2026-11-15》。期间发现并修复：关键词检索漏掉“行程 2.5 万里”（加资料目录和按编号读取）；引用上限 4 条导致数字核对误判（提高到 6 条）；“带我去泸定桥”时多开小测题盖掉跳转（改为只执行第一个操作）；要求说错史实时只拒绝不纠正（提示词要求给出正确说法）。
- 回答依据审计（`npm run audit`，35 个回答）：自动标记 21 个回答、29 句，逐句查看均为“资料没有记载”类说明或衔接、概括句，未发现资料之外的史实。报告见《回答依据审计-2026-11-15》，人工判断栏待填。
- 耗时：常见问题 1.5—3.5 秒，需要多步检索的 3—6 秒。
- Playwright（1440×900、390×844）：步骤在回答出现前逐条显示；“我只有十分钟，想看最惊险的战斗”开始定制路线并退出纯对话；“考考我”打开小测题；无横向溢出，控制台无错误。

局限：模型调用工具的选择有随机性，同一问题多次运行的步骤和措辞会不同；自动判定只查关键词和来源，最终仍需人工对照原文。
