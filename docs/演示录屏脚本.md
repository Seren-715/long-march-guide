> 这是面向评委的**录制操作方案，不是已录制或已通过的证明**。正式录制要用最终公开站点和对应的 GitHub 提交（决定：站点版本号与源码 SHA 一一对应），实际回答、来源、耗时以现场记录为准。
> 这一版按“故事优先”的新界面编写：首页是 37 个有出处故事的转盘，读故事时可以随时问小征，读完沿路线“继续前行”。11-16 版脚本里的节点导览和福建专题仍保留，但压缩到后半段。
> 每一步都已在 `1c85e6e` 上用浏览器实测 3 轮（新会话），见 `docs/演示实测记录-2026-11-19.md`。

## 录制前必须核查

1. 用最终发布版本对应的 GitHub 提交号标注测试记录，记下站点版本号与 SHA 的对应关系。**GitHub 合并不代表站点已发布该版本**。
2. 在最终版本上，每一步至少用 3 个新会话实测，记录完整回答、来源链接、是否出现“未能核对”的降级、耗时。不能剪辑掩盖错误；实测失败时先修复再录制。可以直接重跑实测记录里的浏览器脚本。
3. 读完《四渡赤水》后“继续前行”指向的下一篇取决于本机已读记录：录制要用**干净的浏览器**（无历史），否则下一篇可能不同。
4. 《福建日报》正文“闽西子弟兵近2.6万”的地域范围说明不能漏；“近万”不能当作已核定的准确数，原始统计名册和方法尚未核实。
5. 处理步骤只能称为“引用与数字规则检查”，不能宣称 AI 已逐句核验事实。
6. 录屏前确认：公开访问权限、DeepSeek 账户预算和用量上限、出处链接能正常打开、浏览器里看不到密钥。
7. 如果出现超时、拒答或引用不全，保留真实失败记录并调整脚本，不得凭想象写演示结果。
