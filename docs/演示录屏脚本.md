# 《长征路上》三分钟演示脚本（2026-11-21 修订）

> 这是面向评委的**录制操作方案**，不是已录制的证明。
> - 这一版按赛题“展示 Agent 的交互逻辑”重排：每一段对应小征的一种交互能力，录的时候要让“处理过程”那几行出现在画面里，它就是小征查了什么、为什么重答的直接证据。
> - 每一步都已用浏览器实测 3 轮（新会话），3 轮 × 8 步全部成功；查证说法两步改为在提问框输入后又重跑了 3 轮，同样全部成功。完整回答见 `docs/演示实测记录-2026-11-21.md`。
> - 正式录制要用最终公开站点，并记下站点版本号与 GitHub 提交的对应关系。实际回答以现场为准。

## 分段脚本

| 时间 | 网页操作 | 展示的交互逻辑 | 预期看到（实测） |
| --- | --- | --- | --- |
| 0:00—0:15 | 打开首页。左边是长征路线示意，右边是故事转盘“万水千山，从一个故事说起”，转两张 | **引导式进入**：不用打字，从故事、参观、八闽专题三个入口开始 | 37 个有出处的故事；路线只示意先后，不是行军路线 |
| 0:15—0:35 | 转到《四渡赤水》，点开，按“接着往下看”一段段读完 | **故事阅读与衔接** | 读完依次出现出处、“在这里问小征”、“继续前行”（下一篇《苟坝会议上的马灯》） |
| 0:35—1:00 | 在“在这里问小征”下点“苟坝会议为什么决定不打打鼓新场？”。回答出来后，在输入框打“具体点呢” | **自己查资料、带出处作答**；**无话题追问接回原题** | 回答上方的处理过程：“查阅「赤水河」的资料 · 2 条 → 引用与数字规则检查 · 引用 2 条 · 规则检查通过（非史实核验）”；出处是 `chishui_gouba`、`story_mao_lamp`。“具体点呢”仍讲苟坝会议，展开会议经过、表决和马灯。每步 2—5 秒 |
| 1:00—1:15 | 点这个回答下方的“想了解更多？试试联网搜索” | **联网补查**：带着这一轮的追问去搜 | 处理过程“联网查找 → 整理网络来源 · 3—5 个网页，未经人工核对”；网页来源单独列出，并标明“网络来源 · 未经人工核对” |
| 1:15—1:40 | 点左上角“长征路上”回首页，在提问框打“听说林彪亲自带头冲过了泸定桥，是真的吗？” | **查证说法** | 先说“资料记载的不是这样”，再给资料中的说法：林彪率左纵队，开路先锋是红四团（团长黄开湘、政委杨成武），22 人突击队由廖大珠任队长；最后说明资料中没有林彪本人冲桥的记载 |
| 1:40—1:55 | 在输入框打“带我去飞夺泸定桥那一站” | **操作页面**：模型自己调用 `open_stop` | 处理过程第一行“打开「泸定桥」的讲解”，右侧讲解切到泸定桥，小征简短讲这一站并附出处 |
| 1:55—2:15 | 在输入框打“我只有十分钟，想看最惊险的战斗，帮我安排一下” | **任务规划**：模型自己调用 `plan_route` | 处理过程“规划路线：湘江 → 大渡河 → 泸定桥 → 腊子口”，小征说明安排理由，页面从第一站湘江开始参观，可点“下一站” |
| 2:15—2:40 | 回首页，点“八闽儿女的长征”，问“福建籍参加长征的红军有多少？不同资料为什么数字不同？” | **多种说法并列，不下没有依据的结论** | 三个说法分别引用：福建省政府“近3万”、《福建日报》导语“近2.6万”（正文写“闽西子弟兵近2.6万人”）、省退役军人事务厅专题展“近万”；说明缺少统计名册和方法，无法确定差异原因 |
| 2:40—3:00 | 结束 | 结束语 | 所有馆内回答都附出处；“引用与数字规则检查”是规则检查，不等于史实已被核验；完整测试记录见仓库 `docs/比赛测试记录/` |

备选（时间够或评委追问时）：在首页提问框打“宁化的1300名妇女后来都参加了长征，对吗？”小征会先纠正“1300 名是 1934 年初长征前支前挑粮的人数”，再说明县志没有交代她们后来是否参加长征，所以既不能说都参加了，也不能说都没参加。

## 录制要点

- **把处理过程录进画面**：这是展示交互逻辑的关键。回答出现后，处理过程那几行保留在回答上方，录的时候停留一两秒，或在后期加字幕指出“小征查了哪些资料”“为什么重答”。
- **偶尔出现“核对未通过，重新作答”是正常的**：它说明规则检查拦下了首稿里资料没有的内容，可以保留在视频里作为亮点，不要剪掉。
- **配合《创作文档说明》第三节的流程图**：视频开头或结尾可以放那张“交互总览”图，几秒即可。

## 录制前必须核查

1. 用最终发布版本对应的 GitHub 提交号标注测试记录，记下站点版本号与提交的对应关系。**GitHub 合并不代表站点已发布该版本**。
2. 在最终站点上重跑实测：`DEMO_BASE=站点地址 DEMO_RUNS=3 DEMO_OUT=工作区外的路径 node scripts/demo-check.cjs`。每一步都要得到带出处的回答（联网一步要有网页来源，规划一步要排出路线）。实测失败时先修复再录制，不能剪辑掩盖错误。
3. 用**干净的浏览器**（无历史记录）录制：读完《四渡赤水》后“继续前行”指向哪一篇，取决于本机已读记录。
4. 《福建日报》正文“闽西子弟兵近2.6万”的地域范围说明不能漏；“近万”不能当作已核定的准确数。
5. 处理步骤只能称为“引用与数字规则检查”，不能宣称 AI 已逐句核验事实。
6. 录屏前确认：公开访问权限、DeepSeek 账户预算和用量上限、出处链接能正常打开、浏览器里看不到密钥。
7. 如果出现超时、拒答或引用不全，保留真实失败记录并调整脚本，不得凭想象写演示结果。
